# 现代能源管理系统 (EMS) - 架构与实施主线总结 (v5.0)

> **版本**: 5.0 (Final Approved)  
> **日期**: 2026-01-21  
> **部署模式**: 纯本地化 / 离线部署 (Air-gapped On-Premise)  
> **状态**: 已锁定 (Locked for Implementation)

---

## 1. 项目愿景 (Project Vision)
构建一个**高集成度、纯内网运行**的能源管理数字孪生平台。系统运行在单台工控机上，不依赖外部云服务，利用 Rust 和 TimescaleDB 的高性能特性，实现对工业现场电力数据的毫秒级采集、存储与多维分析，并严格保障多租户数据安全。

---

## 2. 核心架构设计 (System Architecture)

### 2.1 物理部署架构 (Physical Layer)
系统运行在客户现场的单一物理节点（工控机/服务器）上，采用 **Systemd 原生进程管理**。

* **硬件标准**: X86 工控机 (推荐 i5/i7, 16GB RAM, 512GB SSD)。
* **网络拓扑**:
    * `LAN 1` (OT域): 连接 PLC、Modbus 网关、智能电表。
    * `LAN 2` (IT域): 连接内网交换机，供操作员 PC 访问 Web 界面。
* **时间同步**: 依赖主板 RTC 或局域网 NTP 服务器（TimescaleDB 强依赖）。

### 2.2 逻辑软件架构 (Logical Stack)
采用 **“单体模块化 (Modular Monolith)”** 架构，追求极致性能与开发效率。

| 层级 | 组件/技术 | 核心职责 |
| :--- | :--- | :--- |
| **接入层** | **Axum (Rust)** | 集成静态资源托管 (embedded-ui)、Gzip 压缩、API 服务。可选由 LB 卸载 SSL。 |
| **前端** | **Vue 3 + Pinia** | SPA 单页应用，负责交互逻辑、状态管理。 |
| **可视化** | **ECharts** | 实时波形渲染、能耗趋势图表 (LTTB 降采样)。 |
| **后端** | **Rust (Axum)** | **核心大脑**。集成 HTTP API、WebSocket 推送、Modbus 轮询器、TCP 解析器。 |
| **数据层** | **TimescaleDB** | **统一存储**。基于 PostgreSQL 16，存储资产元数据与时序遥测数据。 |
| **运维** | **Systemd/Shell** | 进程保活 (Restart=always)、日志轮转、本地冷备。 |

## 3. 关键架构决策记录 (ADR Summary)

### ADR-01: 纯本地化架构 (No Cloud)
* **决策**: 移除 MQTT Broker 集群和云端 API，所有数据流在本地闭环。
* **理由**: 满足高安全等级工厂（如军工、化工厂）的物理隔离需求，降低网络依赖。

### ADR-02: Rust 一体化后端
* **决策**: 使用 Rust 替代 Java/Go/Python。
* **理由**: 提供 C++ 级的内存安全（防止长期运行后崩溃），无 GC 停顿，适合处理高频工业协议解析。

### ADR-03: 裸机原生部署
* **决策**: 使用 Systemd + Native Packages 部署。
* **理由**: 减少容器层开销，方便 Rust 程序直接访问串口/网口硬件，符合传统工业现场运维习惯。

### ADR-04: 数据库级多租户 (RLS)
* **决策**: 使用 PostgreSQL 行级安全 (RLS) + Realm 模型。
* **理由**: 在数据库内核层强制隔离不同车间/工厂的数据，防止代码层面的 SQL 注入或逻辑漏洞导致数据越权。

## 4. 数据与协议规范 (Data & Protocols)

### 4.1 协议适配策略 (Southbound)
后端 Rust 程序通过异步任务 (`tokio::spawn`) 并行运行采集器：

1.  **Modbus TCP**:
    * **配置驱动**: 通过 JSON 配置寄存器地址、功能码。
    * **复杂处理**: 支持 `CDAB` 等非标字节序转换，支持 `scale` (比例) 和 `offset` (偏移) 换算。
    * **性能优化**: 自动合并相邻寄存器请求 (Batch Read)。
2.  **私有 TCP (0xAA55)**:
    * **帧结构**: `SOF(0xAA55) + VER + LEN + DEV_COUNT + BODY + CRC16`。
    * **处理**: 使用 Rust `Tokio Codec` 实现零拷贝拆包与 TLV 解析。

### 4.2 数据存储模型 (Persistence)
* **静态表 (Postgres)**:
    * `realms`: 租户/领域定义。
    * `users`: 本地账户（Argon2 加密）。
    * `assets`: 设备资产台账（启用 RLS）。
* **动态表 (TimescaleDB)**:
    * `electric_telemetry`: 电力专用超表，按时间分片，启用列式压缩。
    * `hourly_energy_stats`: 连续聚合视图 (Continuous Aggregates)，用于秒开报表。

### 4.3 数据流向 (Data Pipeline)
1.  **采集**: Rust 轮询设备 -> 解析原始字节。
2.  **处理**: 转换为标准结构体 -> 计算实时值。
3.  **存储**: 批量写入 TimescaleDB (Batch Insert)。
4.  **推送**: 通过内存 Channel -> WebSocket 模块 -> 前端 Vue。

## 5. 安全体系 (Security)

由于物理隔离，安全重点在于**内网访问控制**与**数据隔离**。

1.  **认证 (Authentication)**:
    * 完全本地化，不依赖 OAuth。
    * 接口: `/api/auth/login`, `/api/auth/register`。
    * 凭证: JWT (JSON Web Token)，包含 `user_id` 和 `realm_id`。
2.  **鉴权 (Authorization)**:
    * **中间件层**: Rust 解析 JWT，提取 `realm_id`。
    * **数据库层**: 每次查询前执行 `SET LOCAL app.current_realm = ...`，触发 RLS 策略，物理隔离数据。
